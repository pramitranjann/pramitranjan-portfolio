## Decisions
- 2026-08-31 — **Render stills from the same fixture the clips were recorded against.** RBAC's prototype carries two rosters, and the clips and `cover.png` were recorded from `?org=stress` (Aisyah Abdullah, Bakar Halim, `p0@…`), not the default (Amirah Rahman, Jason Lim). Rendering the default put one set of people in the story's stills and a different set in the carousel directly below — one story appearing to show two companies. The clips are the fixed point; the stills follow them.
- 2026-08-31 — **A prototype that will not mount from `file://` needs an HTTP origin, not a fix.** RBAC loads React and Babel from unpkg and both arrived fine, but Babel Standalone fetches the local `.jsx` over XHR and CORS rejects it on a file origin, so `SettingsScreen` was never defined. `python3 -m http.server` in the source directory resolves it with no change to Pramit's prototype. Custom Fields did not need this because its JSX is pre-compiled — so the answer is per-prototype, not general.
- 2026-08-31 — **The bowl and sling Play cards play a silent looping clip instead of a still.** Optional `CaseStudyContent.cardVideo` replaces the image slot on the Play wall card; `heroImage` stays as the poster so the slot is never blank while the clip loads. `CardVideo` in `PlayCard.tsx` is deliberately not `EditorialMediaVideo`: the card is a link, so a click must navigate and the clip carries no controls, no audio track, and pauses under `prefers-reduced-motion`. Source clips were 60s screen recordings — bowl arrived as HEVC, which Chrome and Firefox will not decode, so both were re-encoded to H.264 regardless of trimming: bowl from 0:20 (1080×630, 40s, 2.3MB) and sling from 0:15 (downscaled 2444→1280, 46s, 988KB), audio stripped since autoplay must be muted anyway. Poster paths run through `encodeURI` because the existing preview filenames contain spaces. bowl and sling stay in `AMBIENT_SLUGS` even though a clip bypasses the image rotation, so deleting `cardVideo` restores rotation rather than a frozen still. No dashboard field for `cardVideo` yet — content-only.
- 2026-08-31 — **The Play wall's card order is dashboard-editable, and its assembly has one owner.** `buildWall` lived inside `PlayPageClient` with a hardcoded interleave, so an editor could only reorder cards by editing code. Moved to `lib/play-wall.ts` (`getPlayWallSources` + `buildPlayWall`) because the dashboard's new **Card Arrangement** panel — inside the sidebar's "Play Page" section, `CreativePageEditor` — has to list exactly the cards the visitor sees; two independent copies of the filters would silently reorder a different set. Order is stored as card keys (`game-<slug>`, `photo-<slug>`, `mixed-<slug>`) in `copy.playPage.cardOrder`; absent or empty falls back to the curated interleave, and any card the saved order does not name keeps its default position at the end, so new content can never be invisible until someone opens the dashboard. Reordering reuses the existing `ReorderButtons`/`moveItem` pair every other dashboard list uses rather than adding drag-and-drop. `scripts/check-play-wall.mjs` (`node --experimental-strip-types`) asserts the default, the override, the partial order, and that a stale key for deleted content neither drops nor duplicates a live card.
- 2026-08-31 — **Ambient image rotation on the Play wall is opt-in per card, not a wall-wide effect.** `HoverImageCarousel` only cycled frames on hover, leaving a grid of frozen thumbnails. It now takes an optional `ambientIndex`; passed, the card rotates continuously at rest (1350ms per frame, held one beat first, offset by wall position × 400ms so cards do not flip in unison) and hover no longer touches the images at all. Rotation is split into two effects so a hover cannot reset the ambient phase, and the effect is keyed on frame count rather than the images array so a parent re-render cannot restart it. `AMBIENT_SLUGS` in `PlayPageClient` currently holds `bowl`, `sling`, `south-china-sea`, `hcmc`; bowl and sling have one frame each and stay still until they have art. Omitting `ambientIndex` keeps the original hover-gated behaviour, so `/work` and the section indexes are untouched, and `prefers-reduced-motion` falls back to it. Dropped the hover-time `new window.Image()` preload — `next/image` already renders every frame at mount, so it fetched twice.
- 2026-08-31 — **The carousel's labelled tabs are its only control, on one row at any clip count.** The arrows are removed site-wide rather than hidden for one story; the tabs are real `role="tab"` buttons and touch swipe is untouched, so nothing is lost but a duplicate affordance. The tab strip was `grid-template-columns: repeat(3, minmax(0, 1fr))` — a magic number that silently wrapped the fourth clip onto a second row — and is now `grid-auto-flow: column` over `minmax(0, 1fr)` columns, which holds one row for three clips or five. Labels ellipsise rather than wrap. Pramit's instruction is that this governs every case study unless he says otherwise.
- 2026-08-31 — **A desktop prototype's states are rendered headlessly, not clicked by hand.** The workflow doc's "Pramit runs the renderer" rule exists so the agent does not iterate one command per screen in chat; it is not a requirement that a human do the clicking, and reading it that way cost a full round trip. A headed browser cannot exceed the physical display, so a requested 2200px window silently rendered at ~1800px, overflowed, and pushed the nudge's own action buttons off-frame — the failure looked like a prototype bug rather than a viewport one. Headless has no window and no screen limit. Each Custom Fields state proved to be a single scripted click, and the render asserts `scrollWidth - clientWidth === 0` per shot so a clipped frame cannot pass silently. Playwright lives in the session scratchpad, not in `package.json` — it is a capture tool, not a build dependency.
- 2026-08-31 — **Check what the prototype actually contains before planning stills around it.** Three claims about `custom-fields` were wrong in a row: that Notes was a table column (it is `detail.notes`, drawer-only), that a four-up desktop composite would be legible, and that a transaction carries note text at all. `note` initialises to `""` for every row, so the drawer always reads "Add note" — the nudge asserts "projects in the notes of 14 transactions" and the pills carry `why: "mentioned in 3 recent notes"`, but the note copy was never authored. The planned Research pair collapsed to one still because its evidence does not exist; the nudge banner carries the finding in the product's own words instead, and nothing was typed in for the camera.
- 2026-08-31 — **Desktop case studies get one screen per media slot, not a four-up composite.** The composite is a device that only works when the source screen is narrower than its slot: four 390×844 phones across a 1120px canvas render at ~1.4× native, so the UI reads larger than life, while four 1440px transactions tables across the same canvas render at ~25% linear scale and the table copy lands around 3px tall. Pramit ruled 1-in-1 for desktop stills. Two stills per story rather than eight screens; each is a full-canvas `16 / 9` image with `fit: "cover"` against the app's own `#e4edeb`, so it overfills its figure the way the video fix does and shows no hairline seam at fractional canvas widths. 2200×1238 is the smallest 16:9 viewport at which this prototype's table does not clip — 1440 cut status text mid-word and 1960 clipped once the Project column landed — so the width is measured per prototype, not assumed. `docs/case-study-media-workflow.md` still describes the four-up form and the manual renderer and is now wrong on both counts for desktop stories.
- 2026-08-31 — **A carousel clip earns its place by the claim it makes, not by whether it looks like a shipped interaction.** `alfie-nudge` was proposed for cutting on the grounds that Alfie noticing project names in transaction notes is research framing; that is a category argument and it does not survive contact. It is the only claim in the Custom Fields story that is not table stakes — typed fields, an admin gate and bulk edit are in every B2B tool. The real redundancy question was that three of the four clips run the same loop at different granularities (notice → create one field → accept many values), which is the case for keeping them: they are three distinct claims and a carousel is the one format that can run a three-stage argument without three videos competing. The remaining cost is duration — four clips is a 52s rotation — so the fix is order, not subtraction: the payoff (`create-field`) moves to second and governance (`field-rules`) ends the sequence.
- 2026-08-31 — **The desktop scale is a defined ramp between two widths, not a `vw` coefficient.** `clamp(52px, 3.5vw, 68px)` reads fluid but isn't: with a floor at the base size the growth only spans the sliver of viewport where the `vw` term exceeds the floor, then flatlines. Every desktop value now uses `clamp(base, calc(base + delta * var(--desktop-run)), base + delta)` where `--desktop-run` is `calc((100vw - 1480px) / 1080)` — a length that is 0px at 1480 and 1px at 2560 — so each token interpolates across the whole desktop range and its two endpoints are stated rather than implied. Pramit chose 1.08× type and 1.30× side nav; the rest of the ramp is derived from those. **The ramp is desktop-only by instruction.** Every token it touches is declared inside `@media (min-width: 1480px)`; the base tokens and the `max-width: 767px` phone block (h1 36, h2 28, h3 20, body-lg 16) are untouched and stay that way — Pramit signed off the current phone type on 2026-08-31. Do not fold phone sizes into this scale.
- 2026-08-31 — **The canvas takes a share of new width, it does not claim or refuse all of it.** Freezing the canvas and running it edge to edge are the same rule with the constant flipped, and both fail at the extremes: frozen strands 30% of a 3440px screen in margin, edge-to-edge leaves 1%. `calc(1400px + (100vw - 1480px) * 0.6)` splits every gained pixel 60/40 between composition and margin, so the gutter stays a stable 7–13% of the screen at every size and neither reads as stranded or bled. Pramit rejected the binary toggle as "two extreme solutions to a problem"; the fix was a proportion, not a third preset.
- 2026-08-31 — **Toggles, not sliders, once a value is chosen.** A slider is for finding a number; keeping one after the number is settled just invites drift and leaves the shipped state ambiguous. The three desktop knobs are ON/OFF comparisons against the old composition, and the OFF branch is asserted to reproduce the legacy geometry exactly at 1480/1920/2252/2560px. The statement-size slider stays, because it is a direct px override for exploring, not a settled scale.
- 2026-08-20 — **Pixle Nudge activates through the root layout, not a custom dev script.** This keeps the normal `npm run dev` workflow unchanged; authoring endpoints reject production writes, and installed persistence remains reviewable source in `public/`.
- 2026-08-19 — **Page heroes (eyebrow + h1 + body) share one component.** `WorkPageClient` and `PlayPageClient` had hand-rolled, byte-identical hero markup and duplicated IntersectionObserver eyebrow-reveal logic. Extracted to `components/PageHero.tsx` (wraps the existing `AnimatedEyebrow`); both now render through it. `About`'s hero keeps its own markup since it carries extra elements (CV button, scroll hint) the shared component doesn't model.

Removing the rule touched only the former, so the 32px dash still ships wherever `RuleLabel` is used — the three hero stages, `HeroCarousel`, and every case-study layout. `RuleLabel`'s prop is `number`, so it may be a deliberately different pattern (section numbering, not a page eyebrow); Pramit has not ruled on it. `UnderConstructionPage` and `ScadPageClient` hand-roll the same markup a third time.
- 2026-08-19 — **The homepage film strip derives from content.** `PhotographyStage` hard-coded a five-frame array whose covers and routes duplicated `photography.cities`, so adding a city updated `/play` but never the homepage. It now takes `cities` as a prop and builds one frame per city, numbered in order — which drops the old second KL frame and fixes numbering that previously ran 001, 002, 003, 004, 001. ## Gotchas
- `lib/site-content.ts` throws on malformed content; loading the page is the practical check.
- A `solutionEmbedUrl` replaces the whole Solution chapter: `CaseStudyLayout` drops solution-section media blocks, and `EditorialCaseStudy` renders the embed section instead of the Solution `Chapter`, so `editorialMedia` entries with `section: "solution"` are silently dropped. Get Started is the remaining Swipey story with a live prototype and has only `research`, `decision` and `process` available; dropping the embed, as Custom Fields and Admin did on 2026-08-31, restores Solution. `useEmbedPreview` is only read by the game layout.
- `workPage.projects[]` is separate from `caseStudies[]`; a case study missing from it is unreachable from `/work`.
- Scale embedded iframes with `transform`, never `zoom`; Safari applies `zoom` to the iframe's internal viewport.
- **A `contain` fit whose media ratio matches its container will still expose the container's background as a hairline.** `.editorial-story-media` mattes clips on the light `#e4edeb` product canvas; a 16:9 clip in a 16:9 figure should fill it exactly, but the fluid canvas made the column width fractional, so the browser rounds the painted box to device pixels and the miss shows as a 1px light stroke against the dark page. It was invisible at the old frozen 1120px because every dimension landed on whole pixels. Fixed by overfilling the clipped figure: the contain letterbox inside a box 2px larger is a constant 0.4375px at every width, against a 1px clip. Next's `<Image fill>` sets width/height inline and so cannot be corrected the same way — no editorialMedia entry currently uses `kind: "image"`, but one would need `scale` rather than width/height.
- Graphify excludes `public/proto/**`; indexing vendored bundles floods the graph.
- **A dashboard tab left open across a code push republishes stale content on the next "Publish."** It's a full-document editor with no reload-before-save — every publish overwrites `content/site-content.json` from whatever it loaded, silently dropping any field added by a git commit since. Happened twice this session: a `git push` rejection from a mid-session publish, then (2026-08-19) a second publish that reverted the Swipey tag fix and stripped `photography.cities[].type/shortCode/stripCovers` because the open tab predated the commit that added them — recovered by diffing against the merge base and re-adding the missing fields by hand. If a push is rejected with unfamiliar remote commits, diff against the merge base before merging — don't assume the remote side is empty of surprises.
